# Проверка локального MVP BOTA Group

Дата завершения проверки: 16 октября 2026 (Europe/Moscow).

## Выполнено

- Сохранена существующая реализация без пересоздания проекта; все четыре проектных навыка прочитаны и применены.
- `npm run typecheck` — успешно.
- `npm run build` — успешно, production-сборка Next.js 16.4.1.
- `npm test` — 11/11 записей успешно: 10 предметных подтестов и родительский тест.
- `npm audit --omit=dev --audit-level=high` — известных уязвимостей не найдено на момент проверки.
- Production-сервер запущен на `http://127.0.0.1:3000` с привязкой к loopback.

## Проверено серверными тестами

Публичные страницы, CSP, отсутствие утечки хеша/пароля в HTML, запрет прямых административных API без сессии, отклонение чужого Origin, вход и атрибуты cookie, scrypt, отзыв сессии при выходе, лимит попыток входа, создание/редактирование/удаление карточек, защита от устаревшей версии редактирования, варианты товара, отсутствие исполнения пользовательского HTML, загрузка и декодирование изображения, отклонение SVG под видом PNG, постоянное сохранение WebP, валидация тела запроса и заказа, серверная проверка цены, вариантов, согласия и количества, расчёт суммы, шифрование контактов, идемпотентность, чтение/статус/удаление заказа.

Подготовленные инструкции и исходные изображения не изменены. Их проверка входила в существующий набор тестов.

## Проверено в браузере

Встроенный Chromium, настольная ширина 1440 px и мобильные 390/320 px:

- Главная и каталог, загрузка имеющихся фотографий; видимых сломанных изображений не обнаружено.
- Фото халата, увеличение ×2, закрытие Escape и возврат фокуса.
- Поиск с пустым результатом, фильтр «Халаты», сортировка по убыванию цены (5200, 5100, 4800, 2900), переход в карточку.
- Добавление товара, изменение количества, пересчёт 2 × 2900 = 5800 и 3 × 2900 = 8700 у. е., восстановление корзины после перезагрузки.
- Исправлена дробная величина в корзине: 2,5 приводится к 2. Проверены удаление позиции и пустое состояние.
- Ошибки формы при пустой отправке, фокус первого неверного поля, очищение сообщения при исправлении поля, сохранение тестового заказа с вымышленными контактами.
- Мобильное меню, отсутствие горизонтального переполнения главной, каталога, товара и формы при проверенных ширинах.
- Экран административного входа без настроенного администратора не открывает данные магазина.
- Ошибок/предупреждений в браузерной консоли в проверенных сценариях не обнаружено.

Снимки: `test-results/home-desktop.jpg`, `test-results/catalog-mobile.jpg`, `test-results/checkout-mobile.jpg`. Рабочие тестовые заказы остаются в локальной базе и могут быть удалены владельцем через панель после создания его учётной записи.

## Пределы проверки

Полный сценарий админки в браузере не проверен: автоматическая проверка разрешений отклонила команду создания временной браузерной QA-учётной записи без указания подробной причины. Обход не выполнялся. Вход, CRUD, загрузки и работа с заказами проверены интеграционными HTTP-тестами с изолированными тестовыми данными. Рабочего администратора создаёт владелец через `npm run admin:create`.

Не проведены испытания на физических телефонах, Safari/Firefox, скринридером, нагрузочное тестирование, полный аудит WCAG и независимый аудит безопасности. Нет настроенного коммерческого окружения и реальных платежей/доставки/почты. Размеры и цвета исходных моделей не подтверждены, поэтому поля выбора на витрине появятся после добавления реальных вариантов в админке.

Next.js может вернуть HTTP 200 для not-found после начала streaming; проверены not-found интерфейс и noindex. Это документированное поведение установленной версии.
